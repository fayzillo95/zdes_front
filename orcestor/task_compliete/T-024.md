## Task ID: T-024
### Sarlavha: Axios'ga o'tish — imkoniyat tahlili (faqat tahlil, kod o'zgarmaydi)

**Ijrochi:** AGY

**Persona/uslub (agents/skills/):**
`agents/skills/engineering/engineering-senior-developer.md` uslubida —
arxitektura darajasidagi qaror, keng ta'sir doirasi bor.

**Maqsad (Goal):**
Loyihada Angular `HttpClient` o'rniga (yoki ustiga) `axios` qo'llashning
imkoniyatini tahlil qilib, aniq amalga oshirish rejasini
`orcestor/analysis/T-024-axios-analysis.md` ga yozish. **Bu vazifada hech
qanday kod o'zgartirilmaydi, npm dependency o'rnatilmaydi** — faqat tahlil
va reja (bu reja T-025'ga asos bo'ladi).

**Kontekst (Context):**
- Hozir BARCHA HTTP so'rovlar bitta joyda — `src/app/core/services/http.ts`
  (`Http` klassi) — jamlangan. U Angular `HttpClient`ni o'raydi (`get<T>`,
  `post<T>`, `put<T>`, `patch<T>`, `delete<T>`, hammasi `Observable<T>`
  qaytaradi). Bu — 15+ feature service faylining yagona kirish nuqtasi.
- Ikkita Angular `HttpInterceptorFn` bor: `auth-interceptor.ts` (har bir
  so'rovga `Authorization: Bearer <token>` qo'shadi) va
  `error-interceptor.ts` (401 statusda `Auth.logout()` chaqiradi). Bular
  Angular'ning `HTTP_INTERCEPTORS` DI mexanizmiga bog'liq — axios o'z
  interceptor mexanizmiga (`axios.interceptors.request/response`) ega,
  bular bir-biriga to'g'ridan-to'g'ri ko'chmaydi, qayta yozish kerak
  bo'ladi.
- Barcha 15+ feature service `Http`ning `Observable<T>` qaytaruvchi
  metodlariga bog'liq holda yozilgan (`.subscribe(...)`,
  `takeUntilDestroyed()` bilan, T-019'da yangilangan/yangilanmoqda).
  Agar `Http` ichini axios (Promise-asosli)ga almashtirsak-da, TASHQI
  API (`Observable<T>` qaytarish) saqlanib qolsa, 15+ service faylining
  birortasi ham o'zgarishi shart emas — bu eng kam-ta'sirli yo'l.
- Muqobil (kattaroq ta'sirli) yo'l: butun loyihani Promise/async-await
  arxitekturasiga o'tkazish — bu 40+ komponentga tegishi mumkin.

**Cheklovlar (Constraints):**
- Hech qanday `.ts`/`.html`/`.css` fayliga tegilmaydi, `package.json`
  o'zgartirilmaydi (npm install qilinmaydi) — faqat tahlil.
- Tahlil ikkita variantni ham (kam-ta'sirli: `Http` ichida axios, tashqi
  `Observable<T>` interfeys saqlanadi / katta-ta'sirli: butun loyiha
  Promise'ga o'tadi) solishtirib, ANIQ birini tavsiya qilishi kerak —
  "ikkalasi ham mumkin" kabi noaniq xulosa qabul qilinmaydi.

**Ish doirasidagi fayllar (Files in scope):**

  `src/app/core/interceptors/**`, `src/app/features/*/services/*.ts`
  (namuna sifatida bir nechtasi), `src/environments/**`, `package.json`
- Yozish uchun: `orcestor/analysis/T-024-axios-analysis.md` (yangi)

**Bajarilgan deb hisoblanish mezoni (Definition of Done):**
Tahlil hujjatida quyidagilar bo'lishi shart:
1. Ikkala variantning (kam-ta'sirli / katta-ta'sirli) taxminiy narxi
   (nechta fayl tegishi kerak) va foydasi solishtiruvi.
2. Interceptor'larni (`auth-interceptor.ts`, `error-interceptor.ts`)
   axios'ning `interceptors.request.use`/`interceptors.response.use`
   mexanizmiga qanday ko'chirish kerakligi haqida konkret reja.
3. `environment.apiUrl` bazasini axios `baseURL` konfiguratsiyasiga qanday
   ulash kerakligi.
4. Xato holatlarini (`error-interceptor.ts`dagi 401 handling) axios
   response interceptor'ida qanday takrorlash kerakligi.
5. **Aniq tavsiya**: qaysi variant tanlansin, va T-025 uchun bosqichma-
   bosqich (kichik dispatchlarga bo'lingan) amalga oshirish rejasi.

**Maqsad (Goal):**
To'liq autentifikatsiya oqimini ishga tushirish: `Auth` servisi, `authGuard`,
`roleGuard`, `authInterceptor`, `errorInterceptor` va login sahifasini
to'ldirish — shundan keyin barcha `MainLayout` ostidagi route'lar
autentifikatsiyasiz ochilmaydi.

**Kontekst (Context):**
- `src/app/core/services/http.ts` (T-003'da qurilgan) — generic `get<T>/post<T>/put<T>/patch<T>/delete<T>` metodlari, `environment.apiUrl` asosida ishlaydi. Auth servisi shu servisdan foydalanadi.
- `src/app/core/services/auth.ts`, `core/guards/auth-guard.ts`, `core/guards/role-guard.ts`, `core/interceptors/auth-interceptor.ts`, `core/interceptors/error-interceptor.ts` — hozir bo'sh stub/pass-through holatida.
- `src/app/core/models/user.ts` — hozir bo'sh fayl (interfeys yozilishi kerak).
- `src/app/features/auth/pages/login/login.ts` — bo'sh standalone komponent (`imports: []`).
- `src/app/app.routes.ts` — `auth` route allaqachon alohida, public (layout'siz) sifatida ulangan; qolgan 16 modul `MainLayout` component ostida `children` sifatida joylashgan (T-003'da qurilgan, **struktura o'zgarmasin**, faqat `MainLayout` route'iga `canActivate` qo'shiladi).
- `src/app/app.config.ts` — hozir `provideHttpClient(withFetch())` bor (T-003'dan); interceptor'lar shu yerga `withInterceptors([...])` orqali qo'shiladi.
- Backend API kontrakti hali noma'lum — login endpoint va javob formati uchun taxminiy standart konventsiyani qabul qiling: `POST /auth/login` body `{ username, password }`, javob `{ accessToken: string, user: User }`. Buni kodda **izoh bilan** belgilang — kelajakda backend integratsiyasida moslashtiriladi.

**Cheklovlar (Constraints):**
- Faqat quyida ro'yxatlangan fayllarga tegining — boshqa feature modullarni o'zgartirmang.
- `app.routes.ts`ga faqat `MainLayout` route obyektiga `canActivate: [authGuard]` qatorini qo'shing — boshqa hech narsa o'zgarmasin.
- Yangi npm dependency qo'shmang (masalan `jwt-decode`) — token payload kerak bo'lsa native `atob()`dan foydalaning.
- Token brauzer `localStorage`da saqlansin (kalit: `access_token`).
- `roleGuard` — route `data: { roles: string[] }` bilan ishlashga tayyor bo'lsin (hozircha hech bir route bunday `data` bermaydi, lekin guard mustaqil to'g'ri ishlashi kerak).
- Login sahifasi `ReactiveFormsModule` bilan, standalone component konventsiyasiga mos yozilsin.

**Bajarilgan deb hisoblanish mezoni (Definition of Done):**
- `Auth` servisida: `login(credentials): Observable<User>`, `logout(): void`, `isAuthenticated(): boolean`, `getToken(): string | null`, joriy foydalanuvchini kuzatuvchi holat (signal yoki `BehaviorSubject`) mavjud.
- `authGuard` — token yo'q bo'lsa `/auth/login`ga redirect qiladi, bor bo'lsa `true` qaytaradi.
- `roleGuard` — `route.data['roles']` bilan joriy foydalanuvchi rolini solishtiradi.
- `authInterceptor` — token mavjud bo'lsa har bir chiquvchi so'rovga `Authorization: Bearer <token>` header qo'shadi.
- `errorInterceptor` — 401 javob kelsa `Auth.logout()` chaqirib `/auth/login`ga yo'naltiradi, boshqa xatolarni observable orqali uzatadi.
- Login sahifasi: forma validatsiyasi (bo'sh maydon bloklaydi), muvaffaqiyatli login'dan keyin `/dashboard`ga redirect, xato holatida foydalanuvchiga ko'rinadigan xabar.
- `npm run build` (`ng build`) va `npx tsc --noEmit` xatosiz o'tadi.

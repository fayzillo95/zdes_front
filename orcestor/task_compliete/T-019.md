## Task ID: T-019
### Sarlavha: [Sifat 7] Performance tuzatishlari — OnPush + RxJS subscription cleanup

**Ijrochi:** AGY

**Bog'liqlik:** T-014 (performance tahlili) natijasiga asoslanadi —
`orcestor/analysis/T-014-performance-analysis.md`ni avval o'qing.

**Persona/uslub (agents/skills/):**
`agents/skills/engineering/engineering-frontend-developer.md` uslubida —
bu vazifa asosan takrorlanuvchi (repetitive), ko'p fayl bo'ylab bir xil
naqsh (pattern) qo'llash, shuning uchun izchillik muhim.

**Maqsad (Goal):**
T-014'da aniqlangan ikkita performance muammosini tuzatish: (1) barcha
komponentlarga `ChangeDetectionStrategy.OnPush` qo'shish, (2) barcha
`.subscribe(...)` chaqiruvlarini `takeUntilDestroyed()` bilan xavfsiz
qilish (memory leak oldini olish).

**Kontekst (Context):**
- T-014 topilmasi: loyihada umuman `ChangeDetectionStrategy.OnPush`
  ishlatilmagan — barcha komponent Default strategiyada.
- T-014 topilmasi: `employee-list`, `branch-list` va shunga o'xshash
  ko'plab joyda `.subscribe(...)` chaqirilgan, lekin `unsubscribe()` yoki
  Angular v16+ `takeUntilDestroyed()` operatori umuman ishlatilmagan —
  komponent yo'q qilinganda ham observable davom etishi mumkin.
- Loyiha standalone komponent arxitekturasidan foydalanadi (`@Component`
  dekoratorida `changeDetection: ChangeDetectionStrategy.OnPush` shu yerga
  qo'shiladi).
- `takeUntilDestroyed()` — `@angular/core/rxjs-interop`dan import qilinadi,
  standalone komponentda `constructor()` ichida chaqirilishi kerak (yoki
  `DestroyRef` inject qilinib operatorga uzatiladi, agar `constructor`dan
  tashqarida chaqirilsa).

**Cheklovlar (Constraints):**
- Yangi npm dependency qo'shmang — `takeUntilDestroyed` Angular core'ning
  o'zida bor (`@angular/core/rxjs-interop`).
- Mavjud xatti-harakatni (business logic) o'zgartirmang — faqat
  change-detection strategiyasi va subscription-cleanup qo'shiladi.
- **DataTable'ning client-side pagination'ini bu task doirasida
  server-side'ga o'tkazmang** — T-014'da shu haqda alohida tavsiya bor,
  lekin bu backend hali placeholder bo'lgani uchun (haqiqiy backend yo'q,
  hamma endpoint taxminiy) hozircha sinab bo'lmaydi va alohida, kattaroq
  task talab qiladi. Shu sababli bu T-019 doirasidan **ataylab chiqarib
  tashlangan** — keyinroq, backend real bo'lganda alohida task sifatida
  qaraladi.
- Katta hajm tufayli (40+ komponent) — bitta katta dispatchda emas, kichik
  guruhlarga bo'lib (masalan avval `shared/`, keyin har bir feature
  papkasi alohida) bir necha ketma-ket dispatchda bajaring (xuddi T-017
  uslubida) — oldingi tajriba shuni ko'rsatadiki (T-004), bitta so'rovda
  juda ko'p fayl so'ralsa AGY soxta "tayyor" hisobot berishi mumkin.

**Ish doirasidagi fayllar (Files in scope):**
- `src/app/shared/components/**/*.ts` (barcha shared komponentlar)
- `src/app/features/**/pages/**/*.ts` (barcha list/form/detail sahifalari)
- `src/app/features/**/components/**/*.ts` (masalan `face-register`)

**Bajarilgan deb hisoblanish mezoni (Definition of Done):**
- Har bir `@Component` dekoratorida `changeDetection: ChangeDetectionStrategy.OnPush` bor.
- Har bir `.subscribe(...)` chaqiruvidan oldin `.pipe(takeUntilDestroyed())` qo'llanilgan (yoki subscribe o'rniga `AsyncPipe` ishlatilgan holatlar — bu ham qabul qilinadi, alohida eslatib o'ting).
- `npm run build` va `npx tsc --noEmit` xatosiz o'tadi.
- OnPush qo'shilgandan keyin UI xatti-harakati o'zgarmasligi kerak (masalan `@Input()` orqali kelmaydigan, faqat ichki mutatsiya bilan yangilanadigan holatlar bo'lsa — bunday joylarni alohida ro'yxatga oling, chunki OnPush ular uchun UI yangilanishini to'xtatib qo'yishi mumkin).

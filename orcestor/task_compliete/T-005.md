## Task ID: T-005
### Sarlavha: [Modul 3/10] Shared UI Kit — DataTable, ConfirmDialog, ImageUpload, CameraCapture, Header, Sidebar, Pipe'lar

**Ijrochi:** AGY

**Persona/uslub (agents/skills/):**
`agents/skills/engineering/engineering-frontend-developer.md` dagi Frontend
Developer personasi uslubida bajaring — performance-first, WCAG-ga e'tibor,
va bu safar ayniqsa **qayta ishlatiluvchan (reusable) komponent dizayni**
muhim, chunki bu komponentlarni Modul 5-9 dagi barcha CRUD ekranlar
ishlatadi.

**Maqsad (Goal):**
`src/app/shared/` ichidagi umumiy UI komponentlarini (`DataTable`,
`ConfirmDialog`, `ImageUpload`, `CameraCapture`, `Header`, `Sidebar`) va
pipe'larni (`FullNamePipe`, `AttendanceStatusPipe`) to'liq, generic va qayta
ishlatiladigan holda amalga oshirish.

**Kontekst (Context):**
- Hozir barcha komponentlar bo'sh skelet: `@Component` dekoratori bor, lekin
  shablon/logika yo'q (masalan `src/app/shared/components/ui/data-table/data-table.ts`
  faqat bo'sh klass).
- Loyiha standalone component arxitekturasidan foydalanadi (`imports: []`
  komponent dekoratorida — bu NgModule declarations emas).
- Bu komponentlar keyingi 5 ta modulda (Company/Branches/Departments/Positions,
  Employees, Attendance/Work-schedules/Terminals, Leaves/Holidays/Advances,
  Payroll/Salary-adjustments) barcha list/form sahifalarida ishlatiladi —
  shuning uchun API dizayni **birinchi urinishda to'g'ri** bo'lishi kerak.
- `Header`da joriy foydalanuvchi ismi ko'rsatiladi — bu `Auth` servisidan
  keladi (T-004, Modul 2 avval tugashi kerak).

**MUHIM — avval tahlil, keyin kod (Analysis-first):**
`DataTable` komponentiga kirishdan OLDIN, `orcestor/analysis/T-005-datatable-api.md`
fayliga quyidagilarni yozib chiqing:
1. Taklif qilinayotgan `@Input()`/`@Output()` API (masalan: `columns: ColumnDef[]`,
   `data: T[]`, `loading: boolean`, `(rowClick)`, `(sortChange)`,
   pagination uchun inputlar).
2. Bu API kamida 3 xil taxminiy foydalanish holatiga (masalan: Employees
   ro'yxati — ko'p ustunli, harakatlar bilan; Attendance ro'yxati — sana bilan
   filtrlash; Payroll ro'yxati — hisoblangan qiymatlar) qanday mos kelishini
   qisqacha asoslang.
Shu tahlil yozilgach, amalga oshirishga o'ting. Bu qadam — keyingi modullarda
`DataTable` API'sini qayta yozishga to'g'ri kelmasligi uchun.

**Cheklovlar (Constraints):**
- Yangi npm dependency qo'shmang (masalan `ngx-datatable`, `ngx-pagination`) —
  faqat native Angular + CSS bilan generic jadval/pagination yasang
  (client-side sort/pagination yetarli, backend pagination hali yo'q).
- `CameraCapture` — `navigator.mediaDevices.getUserMedia` orqali ishlasin,
  ruxsat rad etilgan holatni ham handle qiling (foydalanuvchiga ko'rinadigan
  xato xabari, ilova crash bo'lmasin).
- `src/app/features/*` papkalariga tegmang — faqat `src/app/shared/` ichida ishlang.
- Mavjud fayl nomlash konventsiyasiga (standalone component, alohida `.ts`/`.html`/`.css`) rioya qiling.

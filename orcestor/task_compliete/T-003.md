## Task ID: T-003
### Sarlavha: [Modul 1/10] Core infratuzilma — Routing, Environment config va umumiy HTTP servisi

**Persona/uslub (agents/skills/):**
Ushbu vazifani `agents/skills/engineering/engineering-frontend-developer.md` dagi Frontend Developer personasi uslubida bajaring: performance-first, TypeScript bilan aniq tiplashtirish, komponent/servis arxitekturasini kelajakda kengaytirilishi mumkin qilib qurish, workflow "Step 1: Project Setup and Architecture" ga mos — bu bosqichda hali UI emas, balki **poydevor (foundation)** quriladi.

**Maqsad (Goal):**
`zdes-frontend` Angular loyihasining routing va umumiy HTTP infratuzilmasini qurish: (1) `environment` konfiguratsiya fayllarini yaratish, (2) `core/services/http.ts` ni barcha feature servislari foydalanadigan generic, tiplashtirilgan HTTP wrapper sifatida yozish, (3) `app.routes.ts` ni barcha mavjud feature modullar uchun lazy-loaded route'lar bilan to'ldirish, `MainLayout` ichida o'ralgan holda.

**Kontekst (Context):**
- Loyiha hozir **to'liq skelet** holatida: `src/app/app.routes.ts` bo'sh (`export const routes: Routes = []`), `src/app/core/services/http.ts` va `auth.ts` bo'sh stub (`export class Http {}` / `export class Auth {}`), `environment` fayllari umuman yo'q.
- Har bir feature modulida allaqachon `*-module.ts` va `*-routing-module.ts` fayllari mavjud (masalan `src/app/features/employees/employees-module.ts`, `employees-routing-module.ts`) — quyidagi modullar bor: `auth`, `dashboard`, `employees`, `attendance`, `branches`, `departments`, `positions`, `company`, `holidays`, `leaves`, `notifications`, `payroll`, `salary-adjustments`, `settings`, `terminals`, `work-schedules`, `advances`.
- `src/app/shared/components/layout/main-layout/` — bo'sh `MainLayout` komponenti mavjud (header+sidebar bilan o'rash uchun mo'ljallangan, `header/` va `sidebar/` komponentlari ham bor, lekin ular ham hozircha skelet).
- `src/app/core/guards/auth-guard.ts` va `role-guard.ts` mavjud (skelet holatida — bu vazifa doirasida **ularga tegmang**, ular Modul 2 (Auth)da to'ldiriladi).
- Angular versiyasi va konfiguratsiyani `package.json` va `angular.json` dan tekshirib oling (standalone komponentlar arxitekturasi ishlatiladi, `app.config.ts` mavjud).

**Cheklovlar (Constraints):**
- **Faqat shu vazifa doirasida ishlang**: routing skeleti + `http.ts` + environment config. Auth servisi (`auth.ts`), login sahifasi, guard'lar, interceptor'lar — **bu vazifaga kirmaydi**, ularga tegmang (Modul 2 uchun qoldiriladi).
- Feature modullarining ichki tarkibiga (list/form/detail komponentlar) tegmang — faqat ularni `app.routes.ts` ga **lazy-loading** (`loadChildren`) orqali ulang.
- Yangi npm dependency qo'shmang — faqat mavjud Angular imkoniyatlaridan (`HttpClient`, `provideHttpClient` va h.k.) foydalaning.
- Mavjud fayl nomlash konventsiyasiga rioya qiling (masalan `http.ts` ichida klass nomi `Http`, `Injectable` bilan).
- Backend API bazaviy URL manzili hali noma'lum — `environment.ts` ichida placeholder qiymat (`apiUrl: 'http://localhost:3000/api'` kabi) qoldiring va buni izohda (comment) belgilang.

**Ish doirasidagi fayllar (Files in scope):**
- `src/environments/environment.ts`, `src/environments/environment.development.ts` (yangi, agar Angular versiyasi shuni talab qilsa)
- `src/app/core/services/http.ts` (to'ldiriladi)
- `src/app/app.routes.ts` (to'ldiriladi)
- `src/app/app.config.ts` (agar `provideHttpClient` qo'shish kerak bo'lsa, shu yerga qo'shiladi)
- `src/app/shared/components/layout/main-layout/main-layout.ts` (faqat `<router-outlet>` joylashtirish uchun HTML/TS minimal o'zgarishi, agar kerak bo'lsa)

**Bajarilgan deb hisoblanish mezoni (Definition of Done):**
- `ng build` xatosiz o'tadi (`npm run build` yoki `ng build`).
- `app.routes.ts` da barcha 17 ta feature modul uchun `loadChildren` orqali lazy route mavjud, `MainLayout` component ichida joylashgan (bitta ota route, bolalar sifatida feature route'lar), `auth`/`login` esa alohida, layout'siz public route sifatida.
